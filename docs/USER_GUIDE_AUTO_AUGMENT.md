# 强化符文自动识别使用指南

应用在斗魂对局中捕获屏幕，识别采购阶段左、中、右三个强化符文候选，并在屏幕顶部显示只读推荐。顶部窗口不会抢走游戏焦点；独占全屏可能遮住普通桌面窗口，请使用无边框窗口化全屏或窗口模式。

## 使用流程

1. 启动应用和 League Client。
2. 进入斗魂竞技场。应用通过只读 LCU 确认队列和当前英雄。
3. 进入对局后，应用先用小尺寸门禁帧判断屏幕是否出现候选。
4. 确认候选后运行完整 OCR；首次识别完整三卡时显示顶部强化符文推荐弹窗。
5. 自动识别没有及时更新时，按 `F8` 立即触发一次完整识别。

主界面“游戏目录”只是 LCU 自动发现失败时的高级兜底，不是必填项。

## 识别规则

- 首次显示必须读到三个卡位，并通过间距和置信度校验。
- 左、中、右卡位始终对应游戏中的真实位置。
- 切换动画造成瞬时 miss 时保留上一轮完整结果。
- 部分结果只更新已经显示的完整结果，不从空状态打开单卡或双卡弹窗。
- 连续 miss 超过宽限后清空；离开斗魂对局立即清空。
- 当前英雄未知时，不显示按英雄生成的推荐。

## 数据说明

基础字典来自 CommunityDragon。按英雄统计来自 OP.GG adapter，并写入应用数据目录的磁盘 cache。界面展示数据来源和可诊断失败原因。

项目使用平均名次、第一名率、选取率和推荐度。OP.GG 的原始 `win_rate` 口径没有得到验证；界面将它标为“OP.GG 指标（口径未验证）”。

## 设置与排障

“展示强化符文顶部浮窗”控制采购阶段的三卡推荐。“自动注入斗魂装备方案”控制是否把当前英雄的推荐装备写入游戏商店；强化符文推荐本身始终只读。

没有自动识别时依次检查 LCU 是否连接、当前是否为斗魂 `InProgress`、顶部窗口设置是否开启，再按 `F8` 查看日志中的截图、OCR 或数据源失败。OCR 改动提交前运行：

```powershell
npm run test:augment-ocr
```
